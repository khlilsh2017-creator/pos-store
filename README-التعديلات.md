# نسخة المشروع بعد التطوير

تم تجهيز هذه النسخة لتتوافق صفحات النظام مع `worker.js` المرفق. تم تضمين `worker.js` داخل جذر المشروع حتى تكون نسخة النشر مكتملة.

## أهم ما تم إصلاحه

| المجال | التعديل |
|---|---|
| العمليات | تحديث مسارات الإرجاع والإلغاء القديمة إلى `/sales/return` و`/sales/cancel` و`/purchases/return` و`/purchases/cancel` |
| العملاء | إضافة مسارات المدفوعات الحديثة ومدفوعات اليوم ومشتريات العميل في Worker |
| الإعدادات | إضافة `/import-data` للاستعادة الآمنة المقيّدة بصلاحية المدير |
| الذكاء الاصطناعي | إضافة `/ask-gemini` كواجهة وسيطة؛ يلزم ضبط `AI_API_URL` و`AI_API_TOKEN` في متغيرات Worker |
| الطلبات | اعتماد `add_order_ph.html` كصفحة الطلب الحديثة، مع إبقاء `add_order.html` محولًا إليها للحفاظ على الروابط القديمة |
| المندوب | إصلاح جلب تفاصيل الطلب من `/orders/:id` إلى `/online-orders/:id` |
| الإشعارات | توحيد الروابط إلى `/driver/` في Worker وService Workers وصفحة اختبار الإشعارات |
| التنقل | إضافة إدارة الطلبات، تقارير الإنترنت، واجهة المندوب، حركة المخزون، واختبار الإشعارات إلى القائمة المركزية |
| التقارير | إضافة أزرار وواجهة للتقارير المحاسبية المتقدمة |
| القيود | إضافة نموذج إنشاء القيد اليدوي مع التحقق من توازن المدين والدائن |
| التنظيم | إعادة تسمية النسخ المربكة إلى `notification-test.html` و`stock-movements.html` |
| Worker | حماية مسارات الاختبار والتوكنات، وإصلاح حساب صافي الدخل داخل الميزانية |

## متغيرات البيئة الإضافية

لتمكين قسم الذكاء الاصطناعي، أضف إلى إعدادات Worker:

```text
AI_API_URL=https://your-provider.example/v1/ask
AI_API_TOKEN=your-secret-token
```

يجب أن يعيد مزود الذكاء الاصطناعي JSON يحتوي على `answer` أو أن تكون الاستجابة نفسها قابلة للعرض. إذا لم يتم ضبط هذه المتغيرات فستعرض الصفحة رسالة واضحة بدل استدعاء مسار غير موجود.

## طريقة النشر

يجب نشر ملفات الواجهة على نفس النطاق الذي يقدمه النظام، ونشر محتوى `worker.js` على Worker API، ثم التأكد من أن `API` أو `API_BASE` في الصفحات يشير إلى عنوان Worker الصحيح. بعد النشر، امسح كاش Service Worker أو ارفع رقم إصدار الكاش عند الحاجة.

## الاختبارات المنفذة

تم فحص صياغة `worker.js` وملفات Service Worker وجميع JavaScript المضمنة في صفحات HTML. كما تم فحص عدم وجود روابط المسار القديم أو مسارات العمليات القديمة أو أسماء النسخ القديمة داخل ملفات المشروع النهائية.

## دفعة تطوير الواجهات الحالية

تم تطوير الصفحات العادية والضعيفة التالية في الجولة الحالية:

| الصفحة | أبرز التطويرات |
|---|---|
| `payments.html` | واجهة سندات حديثة، العملات المطلوبة، بطاقات إحصائية، بحث وتصفية، إلغاء، طباعة، وتصدير CSV |
| `expenses.html` | دعم العملات والدفع المختلط، اختيار أسماء المصروفات، إحصاءات، سجل جدولي، فلاتر، وتصدير CSV |
| `journal.html` | بحث حسب البيان والتاريخ، إحصاءات، ترقيم صفحات، تصدير CSV، وتحسين عرض تفاصيل القيد |
| `reports.html` | مركز تقارير جديد، ملخص اليوم، مؤشرات مالية، تقارير محاسبية متقدمة، وتصدير JSON/CSV |
| `operations.html` | مركز عمليات منظم، معاينة الفواتير، إرجاعات وإلغاءات المبيعات والمشتريات، ونتيجة العملية |
| `invoices.html` | تفعيل الإرجاع الكامل، تحميل العملاء كاملًا، تحسين الإحصاءات ورسائل أخطاء API، وتحسين أمان العرض |
| `cash-wallets.html` | حماية بيانات العملات والمحافظ والسندات وتحسين العرض عند عدم وجود بيانات |
| `stock-movements.html` | إصلاح pagination باستخدام العدد الكلي من Worker، إضافة روابط التنقل، وحماية أسماء المنتجات والموردين والملاحظات |

بعد هذه الجولة يجب رفع نسخة `worker.js` المعدلة مع الواجهة، لأن endpoint المنتجات يعيد الآن `total` و`page` و`limit` لدعم ترقيم حركة المخزون بشكل صحيح.

## دفعة تطوير دورة الطلبات والبيع والمشتريات والمنتجات

تم تطوير `orders.html` بإضافة تحديث حالة الطلب من نافذة التفاصيل، تسجيل ملاحظة التغيير، وتصدير الطلبات الحالية إلى CSV مع الاعتماد على pagination القادمة من Worker.

تم تحسين `driver/index.html` بحيث تبقى تحديثات التسليم المحلية في طابور IndexedDB عند انقطاع الاتصال، وتُعاد مزامنتها تلقائيًا عند عودة الشبكة، مع منع التكرار عبر `operation_id`.

تم تطوير `add_order_ph.html` بحفظ تلقائي للمسودات، مؤشر حالة الحفظ، وبصمة محلية للتحذير من إرسال طلب مطابق أكثر من مرة خلال فترة قصيرة.

تم تطوير `sale.html` بمسودات بيع محلية وتصدير سجل المبيعات، وقواعد عرض واضحة تسمح بالبيع تحت التكلفة عند تفعيل إعداد النظام، وتسمح بتجاوز المخزون للمنتجات منتهية الصلاحية عند تفعيل `allow_expired_negative_sales`.

تم تطوير `purchases.html` بمسودات مشتريات محلية، استرجاع وحذف المسودات، وتصدير سجل المشتريات إلى CSV.

تم تطوير `products.html` بإضافة تاريخ انتهاء الصلاحية في نموذج المنتج والتفاصيل والتصدير، وإضافة نافذة لعرض المنتجات المعلقة في Worker وتجاهل العناصر التي تمت معالجتها.

تم تحديث `worker.js` بإضافة migration آمنة للحقل `expiry_date`، وتمريره في إنشاء وتعديل المنتج، وإضافة الإعداد `allow_expired_negative_sales`، وتطبيق السماح بالمخزون السالب للمنتجات المنتهية فقط وفق إعداد النظام في المبيعات والطلبات الإلكترونية.

## المرحلة الثالثة والرابعة: العملاء والموردون والإعدادات والتقارير

تم تطوير `customers.html` لإظهار إجمالي الديون من endpoint مخصص مع fallback محلي، وتصدير ملخص العملاء وكشف العميل، وطباعة الكشف، وإتاحة عكس سندات القبض وإلغاء أو عكس الفواتير للمدير فقط.

تم تطوير `suppliers.html` بإظهار إجمالي الديون الحقيقي ومتوسط الرصيد، وتصدير كشوف الموردين وكشف المورد، وإتاحة إلغاء أو عكس فواتير الشراء وعكس السندات والمرتجعات للمدير فقط.

تم تعزيز `worker.js` بحيث تتحقق مسارات المبيعات والمشتريات من دور المدير على الخادم عند الإلغاء أو الإرجاع أو العكس، بما يمنع تجاوز الصلاحية من خلال استدعاء API مباشر.

تم تحسين `settings.html` بمؤشر اتصال مباشر مع زمن استجابة Worker، وإعداد مستقل للسماح بالمخزون السالب للمنتجات المنتهية، وحماية واجهة الاستعادة بحد حجم 20MB وتأكيد كتابي، وإخفاء وظائف النسخ الاحتياطي وإدارة المستخدمين عن غير المدير.

تم تحسين `index.html` بمؤشر اتصال حقيقي، زمن استجابة الخادم، توضيح مصدر البيانات، إظهار دور المستخدم، وزر نسخة احتياطية يظهر للمدير فقط.

تم تحسين `online-reports.html` بمؤشر اتصال، زمن استجابة، وشارة دور المستخدم مع استمرار صلاحية القراءة والتصدير للموظف دون منحه عمليات عكس.

## توحيد المستندات والتقارير

تم إنشاء `document-utils.js` كمحرك مشترك للطباعة والتصدير، وأُدرج في صفحات الفواتير والمشتريات والسندات والعملاء والموردين والمصروفات والقيود والتقارير وطلبات الإنترنت. يوفر المحرك قالبًا موحدًا للفواتير والسندات، مع اختيار المقاس من نفس الشريط: **A4** و**A5** و**إيصال 80mm** و**إيصال 58mm**.

تستخدم فواتير المبيعات والمشتريات والطلبات الإلكترونية قالبًا موحدًا عند الطباعة أو تنزيل PDF، كما أضيفت مستندات مستقلة لسندات القبض والصرف. وأصبحت كشوف العملاء والموردين قابلة للطباعة من حاوية الكشف نفسها بدل طباعة الصفحة كاملة.

أضيف تصدير Excel بصيغة `.xlsx` باستخدام SheetJS، ويستطيع الشريط الموحد تصدير الجداول الظاهرة في الصفحات المالية والتقارير والسجلات. كما تتوفر أزرار PDF وExcel داخل مستند الفاتورة أو السند المفتوح. تعتمد عملية PDF على تحميل مكتبة `html2pdf.js` عند الحاجة، مع حفظ مقاس الورق المختار محليًا للمستخدم.

يجب توفير اتصال بالإنترنت عند أول استخدام لتصدير PDF أو Excel إذا لم تكن مكتبات التصدير محملة مسبقًا، كما يجب تجربة إعدادات الطابعة الفعلية لاختيار A4 أو مقاس الإيصال المناسب قبل التشغيل الإنتاجي.

## المرحلة الحالية: التقارير المتقدمة والإقفال والمنتجات ذات الوحدات

تمت إضافة جداول `daily_product_stats` و`monthly_summary` و`aging_summary` وجدول تدقيق الإقفالات `accounting_closures`، مع الفهارس المطلوبة لتسريع المبيعات وعناصرها والعملاء والمنتجات والطلبات الإلكترونية. كما أضيفت migration آمنة لحقول `unit_type` و`unit_symbol` و`is_decimal_allowed` و`weight_grams` في المنتجات، وإعداد `closed_until_date`.

تمت إضافة دالة `buildFilters` الموحدة، وكاش داخلي للتقارير مع مدد صلاحية مختلفة، ودالة `checkIfClosed` التي تحمي مسارات التعديل المالي الأساسية. كما أضيفت مسارات التقارير `top-products` و`sales-by-product` و`top-customers` و`monthly-trends` و`driver-performance` و`aging`، ومسارا الإقفال `POST /accounting/close-year` و`POST /accounting/reopen` بصلاحية المدير فقط. ينشئ الإقفال قيدًا عكسيًا للإيرادات والمصروفات ويمنع التعديل حتى التاريخ المغلق، بينما تعيد الفتح آخر إقفال وتزيل قيده المرتبط.

تم ربط التقارير الستة الجديدة بأزرار مباشرة في `reports.html`، وإضافة لوحة حالة وأزرار الإقفال وإعادة الفتح إلى `settings.html`. وتم تحديث `products.html` لإدارة الوحدة ورمزها والسماح بالكميات العشرية والوزن بالغرام، مع تمرير البيانات في الإضافة والتعديل والمنتج المعلق. كما تم تحديث `sale.html` و`add_order_ph.html` لتغيير خطوة إدخال الكمية والتحقق من صلاحية الكمية العشرية وفق المنتج.

يشغل المجدول تحديث الجداول الملخصة يوميًا، مع تنظيف كاش التقارير بعد التحديث. وتمت مراجعة احتساب الاتجاهات والملخص الشهري لمنع تكرار إجمالي الفاتورة عند الانضمام إلى عناصرها.

### التحقق النهائي

تم اجتياز `node --check worker.js`، كما اجتازت الصفحات `products.html` و`sale.html` و`add_order_ph.html` و`reports.html` و`settings.html` فحص JavaScript المضمن بواسطة `check_html_scripts.py`. تم التحقق من وجود المسارات الثمانية الجديدة، والحقول الجديدة، وأزرار التقارير، وأفعال الإقفال في الواجهات. يجب اختبار المسارات على بيئة Turso الفعلية قبل النشر النهائي، خصوصًا توفر حساب الأرباح المحتجزة بأحد الأسماء المدعومة في دليل الحسابات.
